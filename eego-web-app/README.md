# Eego

Private English vocabulary and grammar practice, with Japanese explanations and questions generated by your existing ChatGPT-authenticated Codex CLI.

This app lives in **`Logan17de/My-works/eego-web-app`**. It is separate from AIKO and the Language-Learning-App repository.

## Use the web app

The web app is published through ChatGPT Sites. Its owner-private audience is separate from Eego's own login. Sign in with the existing **Mayuna** account and its existing password; this update does not reset it.

- B1–C2 practice bands, vocabulary and grammar filters, Japanese meanings and contextual examples.
- 40 original starter lessons and 80 saved fill-in-the-blank questions. These are estimated learning bands, not the full CEFR corpus.
- Type the missing word or phrase directly into the sentence, then press Enter or Check answer. Answers are checked on the server; case, extra spaces, full-width characters and straight/curly apostrophes are normalized. Spelling still matters.
- The 80 saved starter questions show their Japanese translation before answering, including in older resumed lessons. These translations are bundled with the app; reading one does not mark the answer as a guess. For future generated questions, the UI also accepts a translation supplied with the question and otherwise shows its Japanese hint.
- Persistent history, a separate weak list, due reviews, and JSON progress export.
- A wrong answer, a hint, or an uncertain answer schedules another review. Immediate repetition cannot clear weak status.
- New-question requests go into a durable queue. The app shows whether Codex is actually online.

## Connect your Codex

Run this on the computer or VM where **your Codex CLI is already installed and signed in with ChatGPT**. Python 3.11+ is required. No OpenAI API key is used.

```bash
git clone https://github.com/Logan17de/My-works.git
cd My-works/eego-web-app
python3 worker/connect.py --start
```

If you already have the repo, pull its latest version and run the last command from `eego-web-app`. On Windows, use `python` if that is your Python launcher.

The script checks the Codex CLI and saved ChatGPT login, asks for the existing Eego password in your terminal, creates an account-scoped worker token, and saves it outside Git at `~/.config/eego/worker.env`. It never copies or displays Codex authentication. Keep the terminal running; request a five-question batch in **Generate**. A completed job appears only after generation, an independent model review, validation, and database saving finish.

To restart an already connected worker:

```bash
python3 worker/worker.py --env ~/.config/eego/worker.env
```

Use `--once` to process at most one queued job. For an always-on Linux service, adapt `worker/eego-worker.service.example` to the OS account already authenticated with Codex and its private configuration path. Do not use root merely to avoid file permissions.

**Connection status:** the worker integration is implemented and tested with a fake CLI. Actual Codex inference has not been run by this build because the Harness connector to the owner's machine is unavailable. Nothing runs on that machine until the connection command is started there. The app will correctly display Codex as offline until its heartbeat arrives.

Generation uses the Codex account's available capacity. Quota, login, timeout, or quality-check failures are reported as failures; existing questions remain usable. There is no API-key fallback.

## Build and checks

Requires Node.js 22+ with TypeScript stripping and Python 3.11+. There are no npm runtime dependencies.

```bash
npm run build
npm test
```

`tests/database.sql` is a rollback-only integration suite for the private Eego schema. `tests/test_ui.py` is the earlier mocked browser fixture; it is not evidence of live production browser behavior. Build artifacts are written to `dist/` and should not be committed.

## Backend and deployment

The connected Supabase project is `jxvabaqswqembehxligi`. Eego uses the private `eego` schema and service-role-only `public.eego_api`. The `eego-api` Edge Function performs cookie/session or scoped-worker authentication itself. Its `verify_jwt=false` does not mean the application API is unauthenticated.

The Sites Worker forwards only Eego's cookie to the fixed backend; it does not forward the hosting login cookie. Browser requests remain same-origin. All study records and generated questions are saved in Supabase, not just in browser storage.

For an existing database, **do not rerun `backend/001_schema.sql`**. The worker update adds `workers.user_id` using `003_scoped_worker.sql`, then installs the updated `002_api.sql`. Fresh installations use `001_schema.sql` and `002_api.sql`. Import `data/seed.sql` additively. A fresh installation needs its own account provisioned through an authorized administrative workflow; there is no public signup or hardcoded password.

`supabase/functions/eego-api/index.ts` is generated from `backend/index.ts` by `python3 scripts/prepare_deployment.py`. `web/vercel.json` is retained as an optional deployment configuration, but this version is hosted with Sites. No changes to other applications' deployments are required.

## Validation and limitations

This build passed the local Edge/worker/proxy tests and the rollback-only database suite. A temporary account is used for live HTTPS backend checks, then deleted with its study records. The owner's history is not used as test data. See `DEPLOYMENT_STATUS.json` for the recorded delivery state.

- Real Codex generation and startup on the owner's machine remain unverified until it is connected.
- Hosted-browser visual and cookie QA is not available in this build environment. Backend HTTPS and proxy behavior are checked separately.
- Optional WebMCP controls expose signed-in study status and lesson navigation; supported-browser verification was unavailable.
- This is a starter bank, not the complete sourced B1–C2 inventory. Model review is not professional language review.
- Progress export is supported; import/restore, speech practice, and public registration are outside this version.

Official implementation references: [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode), [Codex CLI commands](https://learn.chatgpt.com/docs/developer-commands?surface=cli), [Supabase Edge authentication](https://supabase.com/docs/guides/functions/auth).
